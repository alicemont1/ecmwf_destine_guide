Request Language Syntax#

When writing a request for Digital Twin (DT) data, you’ll need to use a syntax that is based on ECMWF’s Mars language, with some additional and some modified keywords, specified in the DestinE Keyword Reference table below.

For polytope feature requests, the request dictionary must include an additional key “feature” with a corresponding dictionary as its value. This dictionary specifies the feature-related parameters. These are not part of the standard MARS syntax but follow a similar structure—just with additional key-value pairs specific to Polytope (See more in Feature extraction section).

If you’re just starting out, the following key references will save you time:

  • 📖 The DestinE data catalogue — a complete list of available datasets and parameters.

  • 📖 The Mars keywords reference — useful when building queries for date ranges, time steps, or forecast intervals.

  • 📖 The Polytope Key Value Pairs

Together, these resources will help you build valid requests for DestinE data.

More on Polytope Feature Extraction#

Polytope can enhance standard requests with feature extraction, allowing you to specify a feature keyword that contains a JSON dictionary describing the shape or path of interest. The service then extracts only the points that fall within that feature.

For details on the features that are available for extraction, please check the official guide.

Supported feature types include (availability may vary by dataset):

  • Time series

  • Flight paths

  • Geographic polygons

  • Point extractions

Note

Feature extraction requests return CoverageJSON, not the GRIB format used in standard requests.
