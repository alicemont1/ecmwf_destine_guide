# Request Language Syntax

When writing a request for Digital Twin (DT) data, you’ll need to use a syntax that is based on **ECMWF’s Mars language**, with some additional and some modified keywords, specified in the DestinE Keyword Reference table below.

For polytope feature requests, the request dictionary must include an additional key "feature" with a corresponding dictionary as its value. This dictionary specifies the feature-related parameters. These are not part of the standard MARS syntax but follow a similar structure—just with additional key-value pairs specific to Polytope (See more in Feature extraction section).

If you’re just starting out, the following key references will save you time:
- 📖 The [DestinE data catalogue](https://confluence.ecmwf.int/display/DDCZ/DestinE+Parameter+Portfolios) — a complete list of available datasets and parameters.  
- 📖 The [Mars keywords reference](https://confluence.ecmwf.int/display/UDOC/Keywords+in+MARS+and+Dissemination+requests) — useful when building queries for date ranges, time steps, or forecast intervals.
- 📖 [The Polytope Key Value Pairs](https://polytope.readthedocs.io/en/latest/Service/Data_Portfolio/)

Together, these resources will help you build valid requests for DestinE data.

## DestinE Keyword Reference

Here’s a tabular overview of the most relevant keywords for DestinE requests:

| **Keyword**   | **Applies To**           | **Values**                                                                | **Notes** |
|---------------|--------------------------|----------------------------------------------------------------------------------------|-----------|
| `class`       | climate-dt, extremes-dt  | `d1` , `ng`                                                        | Main category of data (d1 for destine data, ng for nextgems) |
| `dataset`     | climate-dt, extremes-dt  | `climate-dt`, `extremes-dt`                                        | Which dataset to query (*DestinE specific key*)|
| `expver`      | climate-dt, extremes-dt  | `001`                                                              | Experiment version (distinguishes model/data runs) |
| `stream`      | climate-dt               | `clte`                                                             | Climate stream |
|               | extremes-dt              | `wave`, `oper`                                                     | operational data indexed using step, as well as wave model data where needed |
| `activity`    | climate-dt only          | `story-nudging`, `scenariomip`, `highresmip`, `cmip6`, `baseline`  | The CMIP *Activity* that the data is related to |
| `type`        | climate-dt, extremes-dt  | `fc`                                                               | Forecast data |
| `*resolution` | climate-dt, extremes-dt  | `standard`, `high`                                                 | Spatial resolution |
| `experiment`  | climate-dt only          | `tplus2.0k`, `ssp3-7.0`, `hist`, `cont`                            | The CMIP *Experiment* that the data is related to. |
| `generation`  | climate-dt only          | `1`                                                                | Data/model generation |
| `model`       | climate-dt only          | `ifs-nemo`, `ifs-fesom`, `icon`                                    | Model type |
| `realization` | climate-dt only          | `1`                                                                | Ensemble members (Specifies the climate realization. Based on perturbations of initial conditions.) |
| `*feature`    | climate-dt, extremes-dt  | JSON object                                                        | Used for Polytope feature extraction requests |
| `*freequency` | Only for a wave field    |                                                                    |  |
| `*direction`  | Only for a wave field    |                                                                    |  |
| `*levelist`   | ml/pl/sol type data      |                                                                    |  |

`*` optional fields

:::{warning}
The mars "resol" keyword does not work on DestinE data, and instead the key "resolution" should be used to specify dataset resolution.
:::


## More on Polytope Feature Extraction

Polytope can enhance standard requests with **feature extraction**, allowing you to specify a `feature` keyword that contains a JSON dictionary describing the shape or path of interest. The service then extracts only the points that fall within that feature.

For details on the features that are available for extraction, please check the [official guide](https://polytope.readthedocs.io/en/latest/Service/Features/feature/).

Supported feature types include (availability may vary by dataset):
- Time series  
- Flight paths  
- Geographic polygons  
- Point extractions  

:::{Note}
Feature extraction requests return **CoverageJSON**, not the GRIB format used in standard requests.
:::
